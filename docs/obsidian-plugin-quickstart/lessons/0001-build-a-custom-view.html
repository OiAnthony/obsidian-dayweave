构建一个自定义侧边栏 View

完成后，你会得到一个可从 ribbon 打开、不会重复创建、能在右侧边栏自动展开的 Obsidian View。

TypeScriptItemViewWorkspaceLeaf测试 Vault

先建立模型

Plugin在 onload() 注册能力。它是插件的生命周期边界。
ItemView描述一个界面实例，在 onOpen() 中渲染。
WorkspaceLeaf是放置 View 的容器。侧边栏和标签页都由 leaf 承载。

打开界面的动作不是直接 new ItemView()，而是让 Obsidian 将指定的 View type 放进一个 leaf。注册时提供的 factory 负责创建实例。

数据安全：官方文档明确建议不要在主 Vault 开发插件。先创建空白测试 Vault。

1. 跑通官方模板

cd /path/to/test-vault
mkdir -p .obsidian/plugins
cd .obsidian/plugins

git clone https://github.com/obsidianmd/obsidian-sample-plugin.git my-view-plugin
cd my-view-plugin
npm install
npm run dev

打开 manifest.json，至少修改以下字段：

{
  "id": "quickstart-task-view",
  "name": "Quickstart Task View",
  "minAppVersion": "1.7.2"
}

revealLeaf() 从 Obsidian 1.7.2 起可用，因此 manifest 必须声明真实的最低版本。修改 manifest 后重启 Obsidian。

然后在 Obsidian 中打开 Settings → Community plugins，开启 community plugins，并启用 Quickstart Task View。

观察点：当前官方模板从 src/main.ts 构建仓库根目录的 main.js。开发文档中的旧片段可能仍写作 main.ts。

2. 添加 View

新建 src/task-view.ts：

import { ItemView, WorkspaceLeaf } from "obsidian";

export const TASK_VIEW_TYPE = "quickstart-task-view";

export class TaskView extends ItemView {
  constructor(leaf: WorkspaceLeaf) {
    super(leaf);
  }

  getViewType(): string {
    return TASK_VIEW_TYPE;
  }

  getDisplayText(): string {
    return "Quick tasks";
  }

  async onOpen(): Promise<void> {
    this.contentEl.empty();
    this.contentEl.createEl("h2", { text: "Quick tasks" });

    const list = this.contentEl.createEl("ul");
    list.createEl("li", { text: "Open the custom view" });
    list.createEl("li", { text: "Understand its lifecycle" });
  }

  async onClose(): Promise<void> {
    // Release view-owned resources here when needed.
  }
}

TASK_VIEW_TYPE 是内部标识，不是显示名称。所有注册、查找和恢复操作都依赖这个稳定字符串。

3. 注册并打开 View

官方模板的 src/settings.ts 反向引用原插件类。这个练习不使用设置，先删除该文件，再把 src/main.ts 替换为：

rm src/settings.ts
import { Plugin, WorkspaceLeaf } from "obsidian";
import { TaskView, TASK_VIEW_TYPE } from "./task-view";

export default class QuickstartPlugin extends Plugin {
  async onload(): Promise<void> {
    this.registerView(
      TASK_VIEW_TYPE,
      (leaf) => new TaskView(leaf),
    );

    this.addRibbonIcon("list-checks", "Open quick tasks", () => {
      void this.activateTaskView();
    });

    this.addCommand({
      id: "open-quick-tasks",
      name: "Open quick tasks",
      callback: () => void this.activateTaskView(),
    });
  }

  private async activateTaskView(): Promise<void> {
    const existingLeaf = this.app.workspace
      .getLeavesOfType(TASK_VIEW_TYPE)[0];

    let leaf: WorkspaceLeaf | null = existingLeaf ?? null;

    if (!leaf) {
      leaf = this.app.workspace.getRightLeaf(false);
      if (!leaf) return;

      await leaf.setViewState({
        type: TASK_VIEW_TYPE,
        active: true,
      });
    }

    await this.app.workspace.revealLeaf(leaf);
  }
}

官方 Views 指南警告：不要在插件字段中长期保存 View 引用。Obsidian 可能多次调用 factory；需要访问实例时，应通过 getLeavesOfType() 查询。

4. 重载与验证

  1. 确认运行中的 npm run dev 已重新生成 main.js。
  2. 打开 Command palette，执行 Reload app without saving。
  3. 单击左侧 ribbon 的 list-checks 图标。
  4. 折叠右侧边栏，再次单击图标，确认边栏自动展开。
  5. 连续单击三次，确认只存在一个 Quick tasks View。
  6. 停用再启用插件，确认控制台没有异常。
  • View 显示标题和两个列表项。
  • Command palette 也能打开同一 View。
  • 重复打开复用现有 leaf。
  • 重新启用插件后仍可正常打开。

检索练习

用户连续执行三次 “Open quick tasks”。哪一个 API 决定是否复用现有 View？

展开解释

getLeavesOfType() 查找已承载该 View type 的 leaf。没有结果时才创建新 leaf。registerView() 注册 factory，revealLeaf() 负责让已有 leaf 可见。
