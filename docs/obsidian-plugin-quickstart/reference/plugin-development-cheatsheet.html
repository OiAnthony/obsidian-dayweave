Obsidian 插件开发速查

目标不是记住 API，而是掌握从 TypeScript 源码到 Obsidian View 的最短运行路径。

运行链路

src/*.ts→ npm run dev→ main.js→ Obsidian reload→ Plugin.onload()

三个核心对象

对象职责
Plugin注册命令、View、事件和设置；管理插件生命周期。
ItemView定义一个自定义界面实例及其打开、关闭行为。
WorkspaceLeaf承载 View 的工作区容器，例如标签页或侧边栏位置。

生命周期

  • Plugin.onload()：只做注册和轻量初始化。
  • ItemView.onOpen()：向 contentEl 构建界面。
  • ItemView.onClose()：释放 View 自己持有的资源。
  • Plugin.onunload()：插件停用；已注册资源由框架清理。

自定义 View 清单

  1. 定义稳定且唯一的 VIEW_TYPE。
  2. 继承 ItemView。
  3. 实现 getViewType() 和 getDisplayText()。
  4. 在 onOpen() 中渲染 contentEl。
  5. 在插件中调用 registerView()。
  6. 用 getLeavesOfType() 查找现有实例。
  7. 没有实例时取得 leaf，再调用 setViewState()。
  8. 调用 revealLeaf() 展开并聚焦。

资源清理

资源注册方式
Obsidian eventregisterEvent(...)
DOM eventregisterDomEvent(...)
IntervalregisterInterval(...)
ViewregisterView(...)

优先使用框架的注册方法。插件卸载时，Obsidian 才能可靠撤销资源。

常用命令

# 在测试 Vault 的插件目录中
cd /path/to/test-vault/.obsidian/plugins

git clone https://github.com/obsidianmd/obsidian-sample-plugin.git my-view-plugin
cd my-view-plugin
npm install
npm run dev

# 提交前
npm run build
npm run lint

重载规则

  • TypeScript 改动会被 watch build 编译，但 Obsidian 不会自动执行新 bundle。
  • 用 Command palette 的 Reload app without saving，或停用再启用插件。
  • manifest.json 改动后重启 Obsidian。
  • 使用新 API 时同步提高 minAppVersion；本课的 revealLeaf() 要求 1.7.2。

完成标准

  • 构建无 TypeScript 错误。
  • 重复打开只复用一个 View。
  • 侧边栏折叠时能自动 reveal。
  • 停用并重启后无残留事件或异常。
