# 产品启示笔记

## 可迁移设计

### 用默认上下文替代首次分类

捕获工具需要回答“内容先放哪里”。Journal 用今天作为无须选择的答案。这个模式适合工作日志、个人 CRM、研发记录、健康记录和现场采集，但前提是时间本身对内容有意义。

### 同一对象保留两种组织方式

block 既属于某天的父页面，也可引用主题页面。时间顺序保留发生现场，引用图提供语义入口。产品无需在 timeline 与 hierarchy 之间二选一。

### 让结构渐进增加

裸 block、嵌套、引用、tag、property、task 和 query 形成由轻到重的阶梯。用户可停在任何一层。若产品强制每条记录填写固定 schema，就会破坏 Journal 的捕获优势。

### 把回顾设计成写入链路的一部分

指向未来日期的引用会在那天的 linked references 中出现；Deadline 和 Scheduled 也进入当天视图。用户写下内容时已经配置了未来回流，不必另建提醒副本。

## 不应照搬的部分

- 只有内容天然带时间语义时，才应把 daily page 设为默认入口。
- 无限滚动完整页面的实现成本高，动态区块越多，测量和恢复越复杂。
- 自然语言日期必须处理 locale、时区、歧义和可预期性，不能只接一个 parser。
- 自动每日模板应保持短小，并允许关闭。模板越像日报表，捕获阻力越大。
- Journal-first 需要明确的退出路径。当前“关闭 Journals”issue 表明设置入口与核心模型可能发生冲突。

## 评估指标

若在新产品中采用 Journal-first，可观察：

- 从打开产品到完成首条输入的时间。
- 未加分类也能在一周后重新找到的记录比例。
- 每条记录在写入时产生的交互次数。
- linked references、日期回顾和 query 的实际召回占比。
- 自动模板中长期留空或被删除的字段比例。
- 用户关闭、隐藏或绕过 Journal 的比例。
